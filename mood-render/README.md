# Mood Render

Codex에서 재사용하는 건축·인테리어 무드보드 스튜디오입니다. 원본 모델링 이미지와 선택한 레퍼런스를 저장하고, Codex 내장 검색·이미지 생성 도구로 실사화 작업을 이어갑니다. 별도 모델 API 키는 사용하지 않습니다.

## 시작하기

설치된 Codex의 새 대화에서 **Mood Render를 열어줘**라고 요청하세요. 플러그인을 선택할 수 있으면 **Mood Render**를 선택합니다. 기존 대화에 도구가 나타나지 않으면 새 대화에서 시작해야 할 수 있습니다.

1. 프로젝트를 만들고 모델링 화면 또는 렌더 이미지(PNG/JPEG/WebP, 파일당 25MB 이하)를 등록합니다.
2. 원하는 재료와 빛을 입력해 **Codex에 레퍼런스 검색 요청**을 누릅니다. 검색과 후보 수집은 Codex가 담당합니다.
3. 후보를 선택하면 기본값인 Auto가 참고할 요소를 판단합니다. 필요할 때 재료·조명·색감 등의 역할, 적용 대상과 메모를 직접 지정할 수 있습니다. 링크만 있는 후보는 실제 이미지가 추가되어야 실사화에 사용할 수 있습니다.
4. **이 무드로 실사화**를 누릅니다. 내장 UI의 대화 전달이 지원되면 Codex로 요청을 전달합니다. 로컬 화면에서는 실행문을 복사해 Codex 대화에 붙여넣습니다.
5. 생성 결과를 원본과 비교하고, 선택한 결과에서 다음 버전을 만듭니다. 생성 도구가 파일을 반환하지 않는 경우 **결과 등록**으로 이미지를 연결합니다.

## 로컬 화면 실행

Node.js 22.21 이상이 필요합니다. 압축 해제한 폴더에서 `Start.command`를 실행하거나 `node dist/server.mjs --preview`를 실행합니다. 터미널에 표시되는 로컬 주소를 Codex 브라우저로 여세요. 터미널을 종료하면 서버도 종료됩니다. 실행에 npm 설치는 필요하지 않습니다.

로컬 화면은 이미지 편집과 요청 준비를 담당합니다. 검색·생성은 Codex 대화에서 실행하며, 독립 웹페이지가 모델을 호출하지 않습니다. Codex의 내장 도구 제공 여부와 이용 한도가 적용됩니다. 대화가 실행 중이어야 에이전트가 작업을 진행합니다.

## 재설치 가능한 플러그인

ZIP에는 portable `plugin.json`/`mcp.json`과 Codex 호환 `.codex-plugin/plugin.json`/`.mcp.json`, 내장 UI, 번들 서버, 스킬 4개 및 소스가 들어 있습니다. 별도 상시 에이전트 서비스를 설치하지 않고, 스킬이 검색·무드 정리·실사화·검수 역할을 순서대로 수행합니다.

로컬 마켓플레이스에 패키지 폴더를 등록해 설치할 수 있습니다. 현재 컴퓨터의 개발용 마켓플레이스에는 `mood-render@mood-render-dev`로 설치되어 있습니다. 업데이트는 소스에서 빌드하고 마켓플레이스 소스를 갱신한 뒤 재설치합니다. Codex의 설치 캐시를 직접 편집하지 마세요.

## 데이터와 제약

기본 저장 위치는 `~/.codex/mood-render/projects/`입니다. `CODEX_HOME`을 설정한 환경에서는 그 아래에 저장합니다. 프로젝트 폴더에는 원본, 참조, 결과 파일과 JSON이 함께 저장되며, 결과가 원본을 덮어쓰지 않습니다. 백업 시 이 데이터 폴더를 별도로 복사하세요. 플러그인 ZIP에는 사용자 이미지와 프로젝트가 포함되지 않습니다.

실사화 요청 시 무드보드 상태를 고정해 이후 편집과 구분합니다. 여러 창의 저장 충돌을 감지하며, 비정상 종료된 저장 잠금은 약 10초 뒤 재시도하면 회복됩니다. 원본의 형태 유지 지시는 생성 모델의 제약이므로 정확한 치수나 동일 형상을 보장하지 않습니다.

검색 후보의 출처 URL을 기록합니다. 웹의 이미지 접근 제한을 우회하지 않으며, 파일을 얻지 못한 후보는 링크 후보로 유지합니다. 내장 이미지 도구가 참조 수 제한 때문에 모든 이미지를 받을 수 없으면 참조 수를 줄이는 등 사용자 선택이 필요합니다.

## 개발 및 검증

`npm ci` → `npm run check` → `npm test` → `npm run package` → `npm run verify:package` 순서로 실행합니다. 패키지 생성/ZIP 검증 스크립트는 macOS의 `ditto`를 사용합니다. 번들 서버는 Node.js로 실행합니다.

검증 범위: MCP 도구·UI 리소스 로딩, 프로젝트 재열기, 동시 저장, 충돌 복구, 이미지 검증, 무드보드 스냅샷, 결과 버전 관계, 로컬 브라우저 편집·요청 준비. 실제 사용자 이미지 실사화와 Codex 내장 UI의 대화 전달은 별도의 사용 검증이 필요합니다.
